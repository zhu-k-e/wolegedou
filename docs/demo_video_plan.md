## 二、怎么录制（技术准备 · 前后端两台机器，勿默认同屏）

### 2.1 环境与连通（录制前必须跑通）
1. **启动后端**（PyCharm 用已生成的 `Backend Server` run config，reload=False，避免僵尸占 8000）：
   ```
   .venv\Scripts\python.exe -m backend.main
   ```
2. **开 Cloudflare 隧道**（队友连这个 URL，不在局域网也能访问）：
   - 程序：`cloudflared.exe/cloudflared-windows-amd64.exe`
   - 启动后抓 `https://*.trycloudflare.com` 域名（**每次重启换域名，旧 URL 立即失效**）
   - 前端把 API base 指向该 URL，先 `curl <URL>/health` 验 200 再录
3. **前端**：队友确认能发 `POST /api/ask` 并接收 `WS /ws/{task_id}` 实时状态。

### 2.2 录屏设置（OBS Studio）

- 工具：OBS Studio（免费），**1080p / 30fps**，采集「系统音频 + 麦克风旁白」。

#### 「多智能体协同调度可视化」证据从哪来
| 来源 | 所在机器 | 形态 | 必要性 |
|---|---|---|---|
| **前端 WS 驱动的 7 步流转动画** | **队友机器** | 打磨过的产品级可视化 | ✅ **必须，队友屏幕已自带** |
| 后端终端 loguru 原始调度日志 | **本机** | 一行行 `FSM转移`/`段N审核`/`降维解释完成` 原始 trace | ❌ 可选补充 |

> 评分要求的是"调度过程可视化"，**前端那套 7 步动画已满足**，队友无需看到你的后端终端。右 40% 后端终端屏不是跨机器硬要求，只是可选技术佐证。

#### 两种落地方式（二选一）
- **方式①（推荐）：整套在你本机录**。浏览器打开队友部署的前端（走 cloudflared 隧道 URL）放左 60%，你的后端终端放右 40%，OBS 录本机桌面 → 正好 60/40 分屏、零同步问题。队友仅需保证前端在线 + 隧道通畅。
- **方式②：各录各的再拼接**。队友录前端、你录后端终端，剪映/PR 拼接（**拼接完全可行**）。代价：多一道剪辑、有音画对齐风险。

- **旁白**：边操作边讲「现在输入的是哪种学情」「现在哪个 Agent 在工作」「生成了哪几种资源」。

### 2.3 预演与控时
- **正式录前空跑 3 遍**：3 个问题各跑一次，确认都在 ~2 分钟内出结果（避免 API 超时卡顿）。
- 总时长严格 **≤ 10:00**，建议 **9:30** 收尾留余量。OBS 开「录制计时」。
- 隧道若中途断：立刻重启 cloudflared 拿新 URL → 前端重连 → 从断点场景续录（不要硬扛黑屏）。

## 六、避坑与质检清单（录完必查）

5. **修复参考文献重复堆砌**：同一文档重复列出十几次像溯源 bug，录制前让前端/后端去重。
6. **不要展示报错/强制放行流程**；TC-048 的 `low_confidence_passed` 是正常低置信通过，旁白说明即可。
7. **隧道断了立刻重启换 URL**，前端重连后从断点续录；不留黑屏/卡顿。
8. 三个问题必须都跑通且闭环完整，无「生成到一半没了」的片段。
9. 录完用剪映粗剪：删停顿、保证 ≤10:00、导出 1080p MP4。
