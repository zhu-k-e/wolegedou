# 10 分钟演示视频录制计划书（XH-202630）

> 用途：与前端队友一起录制题目硬性要求的「10 分钟以内系统演示视频」。
> 题目原文要求视频需清晰展示：**从差异化学情画像输入 → 多智能体协同调度与交互过程可视化 → 最终个性化领域知识资源生成的完整闭环**。
> 本计划书的 3 个问题严格对应我们已最终化、零假标的 3 组 showcase 用例（TC-001 / TC-020 / TC-048），视频展示内容即证据里真测过的内容，前后一致。

---

## 一、录制目标（对齐评分点）

| 评分维度 | 本视频要证明的点 |
|---|---|
| 完整性 30 | 全流程闭环：学情画像 → 多 Agent 协同调度 → 资源生成 → 反馈 → 动态迭代 |
| 创新性 25 | 辩论/交叉验证消幻觉、知识溯源、动态追问导学 |
| 用户体验 15 | 界面简洁、Agent 调度过程可视化流畅、3 形态资源排版清晰 |
| 实用价值 30 | KB 切片 + 3 组差异化学情测试用例；诚实指标（幻觉 3.0% / 适配 100% / 谬误 0% / 覆盖率 87.9%） |

## 二、怎么录制（技术准备）

### 2.1 环境与连通（录制前必须跑通）
1. **启动后端**（PyCharm 用已生成的 `Backend Server` run config，reload=False，避免僵尸占 8000）：
   ```
   .venv\Scripts\python.exe -m backend.main
   ```
2. **开 Cloudflare 隧道**（前端队友连这个 URL，不在本机局域网也能访问）：
   - 程序：`cloudflared.exe/cloudflared-windows-amd64.exe`
   - 启动后抓 `https://*.trycloudflare.com` 域名（**每次重启换域名，旧 URL 立即失效**）
   - 前端把 API base 指向该 URL，先 `curl <URL>/health` 验 200 再录
3. **前端**：队友确认能发 `POST /api/ask` 并接收 `WS /ws/{task_id}` 实时状态。

### 2.2 录屏设置
- 工具：OBS Studio（免费），**1080p / 30fps**，采集「系统音频 + 麦克风旁白」。
- **分屏布局建议**：左 60% 前端界面，右 40% 后端终端（实时滚动 Agent 调度日志）；或前端全屏 + 右上角画中画后端日志。右屏是「多智能体协同调度可视化」的直接证据，**必须有**。
- 旁白：边操作边讲「现在输入的是哪种学情」「现在哪个 Agent 在工作」「生成了哪几种资源」。

### 2.3 预演与控时
- **正式录前空跑 3 遍**：3 个问题各跑一次，确认都在 ~2 分钟内出结果（避免 API 超时卡顿）。
- 总时长严格 ≤ 10:00，建议 9:30 收尾留余量。OBS 开「录制计时」。
- 隧道若中途断：立刻重启 cloudflared 拿新 URL → 前端重连 → 从断点场景续录（不要硬扛黑屏）。

## 四、要录制的问题（3 组差异化学情，严格对应 TC-001/020/048）

> ⚠️ **硬性红线（录前必读）**：本节的**画像取自 `data/io_examples/bm_TC-XXX_io.json` 的 `input_profile` 真值**，**问题文本取自 `tests/test_cases_100.json` 的基准原文**。
> 二者必须与提交的 I/O 示例文档**逐字一致**——**禁止改写问题措辞、禁止替换画像字段**。理由：评委可拿视频对照我们提交的 `data/io_examples/` 样例与 `benchmark_evidence_100.json`；若视频问题/画像与文档不一致，会暴露"视频与证据不是同一组"，直接削弱可信度。
> 三组刻意覆盖「入门 / 中级 / 进阶」三档，且背景不同（CS 学生 vs 开发者），直接证明「差异化适配」。

### 问题① — 入门档（对应 TC-001，ID 在基准中为 `TC-001`）
- **学情画像（io_examples 真值）**：`knowledge_level=入门` / `background=cs_student` / `domain_hint=["LLM基础"]` / `question_type=概念理解` / `current_goal=深入理解原理` / `complexity_estimate=单领域` / `intent_type=generation`
- **输入问题（test_cases_100.json 原文，禁止改写）**：「在大语言模型中，什么是 Token？它与"词"有什么区别？」
- **预期产出**：基础概念讲义 + 可运行的小示例 + 5 道概念测验（含选择/判断/简答）

### 问题② — 中级档（对应 TC-020，ID 在基准中为 `TC-020`）
- **学情画像（io_examples 真值）**：`knowledge_level=中级` / `background=developer` / `domain_hint=["Agent框架"]` / `question_type=概念理解` / `current_goal=项目落地` / `complexity_estimate=单领域` / `intent_type=generation`
- **输入问题（test_cases_100.json 原文，禁止改写）**：「请解释 ReAct（Reasoning + Acting）范式的工作流程，Thought-Action-Observation 循环是如何进行的？」
- **预期产出**：含 Thought-Action-Observation 循环的讲义 + 可执行代码示例（实操指南）+ 5 道进阶测验

### 问题③ — 进阶档（对应 TC-048，ID 在基准中为 `TC-048`）
- **学情画像（io_examples 真值）**：`knowledge_level=进阶` / `background=developer` / `domain_hint=["Agent框架"]` / `question_type=操作步骤` / `current_goal=项目落地` / `complexity_estimate=单领域` / `intent_type=generation`
- **输入问题（test_cases_100.json 原文，禁止改写）**：「请设计一个多 Agent 协作流程，包含规划 Agent、执行 Agent、审查 Agent，说明数据如何流转。」
- **预期产出**：多 Agent 规划类讲义 + 分步操作指南 + 5 道设计型测验；verdict 可能为 `low_confidence_passed`（正常低置信通过，非兜底）

> 📌 **前端表单录入注意**：`background=cs_student` 不是 `StudentProfile` 的严格枚举值（枚举为 `文科/理科_无编程/有Python基础/有ML基础`），它由后端 `_coerce_profile` 容错兜底。前端若用下拉表单，请将 CS 生映射到最近有效值 **`有Python基础`**；若用自然语言输入（`profile` 留空）则走学情诊断 Agent 自动解析，不受影响。

## 五、必展示亮点清单（对照得分点，逐项打勾）

- [ ] **多智能体调度可视化**：`WS /ws/{task_id}` 实时显示学情诊断→领域生成→审核裁判的状态流转（右屏日志或前端状态条）
- [ ] **辩论消幻觉**：展示裁判团/Verifier 对候选输出的交叉验证与驳回/通过（前端有 debug 面板则展示，否则用后端日志分屏）
- [ ] **知识溯源**：生成内容中 `verify_statement` 溯源标记 / 引用来源状态（已验证 / 未命中KB检索）
- [ ] **3 形态资源**：讲义（lecture）、实操指南（practice_guide）、分阶测验（quiz）同屏或顺次展示
- [ ] **可视化报告**：盲区热力图 + 难度曲线 + 学习路径（来自 `/api/report`）
- [ ] **动态迭代**：降维解释 / 进阶挑战 按答题正确率自动追加（来自 `/quiz_submit` 触发）
- [ ] **差异化适配**：问题①与②用不同画像，资源难度/风格明显不同

## 六、避坑与质检清单（录完必查）

1. **不要展示报错/强制放行流程**；TC-048 的 `low_confidence_passed` 是正常低置信通过，旁白说明即可，不要当成缺陷。
2. **覆盖率诚实表述**：只说「87.9%」，绝不可说「90% 以上」或「全覆盖」——评审若核对证据会发现矛盾，违反竞赛铁律。
3. **隧道断了立刻重启换 URL**，前端重连后从断点续录；不要留黑屏/卡顿片段。
4. **三个问题必须都跑通且闭环完整**，无「生成到一半没了」的片段。
5. **右屏日志/前端状态必须能看到 Agent 流转**，否则「多智能体协同调度可视化」这一评分点不成立。
6. 录完用 OBS 自带剪辑或剪映粗剪：删停顿、保证 ≤10:00、导出 1080p MP4。
7. 视频文件名建议：`作品演示视频_领域知识个性化生成与多智能体协同决策系统.mp4`
