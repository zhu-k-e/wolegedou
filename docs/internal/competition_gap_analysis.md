## 三、提交形式 / 合规缺口

### 1. 数据合规与脱敏（五(5)）⚠️ 文档声明缺口
- 后端**无显式**用户画像/交互记录脱敏或隐私处理代码（grep 仅命中"候选 Agent 质疑匿名化"，非用户 PII）。
- 实际用的是**合成学情数据**（非真实个人信息），风险低；但评审看书面材料，必须在 `proposal.md`/`README` 声明："全程使用合成脱敏学习者数据，未采集真实个人敏感信息，符合隐私保护要求"。
- 加分项：存储层说明"session 级匿名 ID、不存姓名/手机号等 PII"。

### 2. Dockerfile ⚠️ 可选
- `requirements.txt` + `README` + `SETUP` 已有部署说明，无容器化不影响提交（作品提交形式(2)要求"部署说明"而非必须 Docker）。
- 建议补全 Dockerfile，提升评审"一键跑通"印象。部署说明应补 OMP 段错误 workaround 提示（torch 段错误已根治于 sitecustomize）。

- 内容：差异化学情画像输入 → 多智能体协同调度可视化 → 最终个性化资源生成完整闭环。

### 4. 材料文档 —— 文档
