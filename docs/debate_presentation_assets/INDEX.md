## 架构全景图 (multi_agent_debate_flow.svg)

包含 4 层信息：

1. **顶层**：8 个 FSM 主流程状态（PROFILING → COMPLETE）
2. **JUDGING 展开层**：3 人裁判团（事实/逻辑/适用性）+ 分歧解决状态机 + 候选辩论 + 终审门控 + 快速通道
3. **防幻觉链路**：RAG → Agent自评估 → 审核团队 → 裁判团 → 代码检查，5 道防线
4. **底部指标卡**：≥90%溯源率 / <5%幻觉率 / ≥85%适配率 / ≥90%覆盖率

## 演示脚本 (debate_demo.py)

### 场景设计

- **提问**："什么是注意力机制？它在Transformer中的作用？"
- **学生画像**：入门、无编程背景、快速上手
- **聚焦输出**：含一个精妙的"事实偏差"——步骤4写"Google 2017年最早在机器翻译任务上验证了其有效性"，但注意力机制是 Bahdanau 2014 提出的

### 6 阶段展示

| 阶段 | 内容 | 看点 |
|------|------|------|
| 1 | 输入信息展示 | 学生画像 + 聚焦输出结构 |
| 2 | 反向怀疑检测 | refs=3/code=9/steps=5 未触发，常规审查 |
| 3 | 3人独立审查（并行） | 事实审查 fail（发现偏差）+ 逻辑 pass + 适用性 pass → 2:1 |
| 4 | 分歧解决 | 少数方举证 → 多数方反驳 → 僵持 → 裁判长终裁 → revise |
| 5 | 溯源标注 | 8条声明全部溯源验证 → 100%验证率 |
| 6 | 最终裁定 | revise，退回 FOCUSING 阶段重做 |

### 关键机制展示点

- **事实偏差被精准捕获**：不是一个大错误，而是"步骤4表述易产生误解"——这体现裁判团不是简单检查"对/错"，而是检查*表述精确性*
- **分歧解决完整走通**：2:1 触发，少数方举证，多数方反驳，僵持后裁判长终裁——比多数同类系统仅投票汇总更深入
- **溯源标注扩展**：除了 knowledge_refs 的 3 条，还将 conclusion(1) + reasoning_steps(4) 纳入——共 8 条声明，全部验证通过，体现防幻觉覆盖率

## 使用方法

### 直接运行演示

```bash
python docs/debate_presentation_assets/debate_demo.py
```

### 修改演示场景

编辑 `debate_demo.py` 中的 `DEMO_FOCUSED_OUTPUT`、`judge_fact_review()` 等模拟函数即可：

- 想展示"反向怀疑触发"：把 refs 改到 ≥5
- 想展示"快速通道"：把审核评分改到分差 <0.05
- 想展示"0:3 全票失败终审"：把 3 位裁判都设为 fail
