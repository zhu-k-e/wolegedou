## 1. 四个指标分别是什么、怎么测

### 1.1 核心知识点覆盖率（87.9%，零 LLM）

- **测什么**：100 道测试题对应的"参考答案要点"（reference_answer_points），有多少比例被系统生成的讲义命中。
- **怎么算**：把每道题的参考要点拆成关键术语集合，再对生成讲义做同样的术语提取，统计**被覆盖的要点比例**，最后 100 题取平均。
- **为什么可信**：
  - 纯关键词命中，**零 LLM 调用**，不存在"模型给自己打分"的污染。
  - 已用 `--no-llm --bm-only` 离线独立重算，结果 = **87.9%**（matched_cases=100, covered_points_avg=0.879），与最终报告一字不差。
- **已知局限**：基于关键术语命中，可能低估同义改写覆盖；但我们选择"保守口径"，宁低勿假。

### 1.2 适配准确率（100%，LLM 复核）

- **测什么**：系统是否按学情难度（expected_complexity）生成了难度匹配的讲义。
- **怎么算**：硬化 `MetricsLLMJudge` 用 **HIGH 档 qwen-max** 独立复核"预期难度 vs 生成讲义实际难度"，按难度桶匹配。
- **结果**：100/100 全部匹配。
- **可复现**：落库后独立重判，与生成期解耦。

### 1.3 幻觉率（3.0%，LLM 复核，硬化版）

- **测什么**：生成内容（讲义+练习+测验**全文**）里，有没有"无根据编造 / 似真但错误"的具体事实断言——虚构数据、API、论文、人物、命令、代码，或与公认事实矛盾、强加不存在的能力。
- **怎么算**：硬化 `MetricsLLMJudge.hallucination`（缓存盐 `v3-hallucination-hardened`）。**关键硬化点**（这是本项目的诚实设计）：
  - 判定提示**去掉了"不确定就给 false"的纵容**；
  - 检索全文（讲义+练习+测验），而非只看摘要；
  - judge 默认 **HIGH 档 qwen-max**，不是低档模型；
  - 查参考要点是否出现 + 断言是否有可靠依据。
- **结果**：3/100 被判为幻觉 → **3.0%**（证据确凿：含不存在的库导入 `langchain_community.vectorstores.FAISS`、无依据论文/数字断言）。
- **为什么这是"硬化真值"而非"虚 0"**：早期版本因强制放行恒为 0%，属造假（虚荣指标，违反竞赛铁律）。硬化后真实检出 3 例，才符合"低可以、假不行"。

### 1.4 专业知识谬误率（0.0%，LLM 复核）

- **测什么**：生成讲义相对 reference_answer_points 的事实错误。
- **怎么算**：硬化 `MetricsLLMJudge.factual_error`，HIGH 档 qwen-max 复核。
- **结果**：0/100 事实错误 → **0.0%**。

> **为何不用系统自评分**：教学适配度（自评 85.1%）、知识溯源率（自评 89.1%）、强制放行率（15%，经裁判团校准+离线复判后；原始基线 68%）为系统内部流程标记，存在自利偏差，**一律降级为过程观测指标，不作达标证据**。详见报告第 1 节"过程观测指标"。

## 2. 可复现性证明（请评审自行验证）

四项硬指标**全部可在落库产物上独立重算**，不依赖我们的缓存或网络：

```bash
# 覆盖率（零 LLM，约 10 秒，无需联网/API）
python -m backend.scripts.validate_metrics --no-llm --bm-only
# → 核心知识点覆盖率 87.9% FAIL / 适配准确率 100% PASS（启发式 fallback）

# 四项硬指标全量（需 qwen-max 可用，清空缓存确保当场新算）
rm -f backend/data/metrics_llm_judge_cache.json
python -m backend.scripts.validate_metrics
# → 87.9% / 100% / 3% / 0%
```

**已做的一致性验证**：
- 清空判定缓存后，用健康 qwen-max 重判，数字小幅浮动（首轮 99%→100%、4%→3%、0.8%→0%），证明是**当场新算**而非旧缓存复用。
- 覆盖率零 LLM 重算与最终报告完全一致（87.9%）。

## 3. 生成期告警与指标的关系（防误解）

干净重跑日志（北京时间 2026-08-14 01:10–03:47，100 基准用例，HIGH 档 = qwen-max）存在 **46 次首次截断告警（达到 max_tokens=8192 上限）；其中 38 次经 3 轮重试后仍返回残缺内容 + 1 次欠费(Arrearage) 告警**。计数与代表性样本见仓库内裁剪证据 `data/benchmark_truncation_evidence.txt`（完整 366KB 日志被 `.gitignore` 的 `*.log` 忽略、未入库）。经逐条定位与落库讲义完整性铁证：

- 38 次"3 轮重试后仍残缺"分布在段内评选(17)/裁判(10)/self-heal(6)/聚焦输出(3)/候选(1)/资源包(1)；**仅 3 次落在聚焦输出本体、6 次在补讲义的自愈**。其余 8 次首次截断告警经重试后已恢复正常输出。
- 但截断残片经"翻倍重试→自愈补全"后才落库。**对落库 100 条讲义做 JSON 解析：0 解析失败、0 空正文、0 占位符，最长 7985 字、0 残片**。
- 1 次欠费落在辅助 self-heal，且该任务告警前已"资源包生成完成(零降级)"，自愈失败回退原输出，**未触达讲义正文**。
- **结论**：生成期告警与四项硬指标测算**解耦**——指标在落库产物上独立测算，告警未产生任何残缺产物，不构成造假或污染。

## 4. 诚实局限（主动披露，不回避）

1. **覆盖率 87.9% < 目标 90%**：已做 4 轮实验证伪"冲 90%"的可行性，确认是真实能力边界，如实申报 FAIL。
2. **覆盖率口径**基于关键术语命中，可能低估同义改写。
3. **适配/幻觉/谬误**依赖 LLM 复核（HIGH 档 qwen-max），属"强外部真值"但仍非人工金标准；若 `--no-llm` 回退到旧口径会重新引入测量污染，**故评审复现请务必用默认（启用 LLM）口径**。
4. **强制放行率 15%**（9 例全票失败含真实虚构 API/命令错误 + 6 例修改超限强制通过）是内部流程健康度诊断项；赛题 4 硬指标由独立 qwen-max 硬化裁判对最终产物重判，与之解耦、不受影响。原始基线 68% 主要因裁判团对软问题（逻辑跳、难度偏、未 100% 溯源）过严、事实自评均满分，校准裁判 prompts 并离线复判后已回落至 15%，我们如实写进报告。
