## 一、整体定位变化

| 维度 | 现在（v6.13） | 改后 |
|------|-------------|------|
| 架构性质 | **固定流水线**：查表→独立生成→外部评分→外部裁判 | **动态圆桌协同**：自参选→可见彼此→讨论→自收敛 |
| 四模块 | 学情诊断 + 领域生成 + 审核+裁判 + 贡献记忆 | **三模块**：学情诊断 + 圆桌协同(生成+讨论+收敛) + 贡献记忆 |
| Agent总数 | 17（10领域+3审核+3裁判+1资源） | **12**（10领域+1协调+1资源） |
| 论文映射 | 贴标签引用 | **真正落地** |

### DyLAN — 真正的动态组合

| DyLAN核心发现 | v6.13声称 | v6.13实际 | 重构后真正落地 |
|--------------|----------|----------|-------------|
| Agent Importance Score驱动选人 | "Agent池动态贡献分(2.4)" | 查表分配，Agent不自选 | **Agent自评估置信度→主动参选**，importance_score驱动参选权重 |
| 动态组合 | "动态组队" | 固定每段2人 | **按置信度阈值>0.6自参选，不足则征召补充** |

### Debate — 真正的辩论与证据裁决

| Debate核心发现 | v6.13声称 | v6.13实际 | 重构后真正落地 |
|--------------|----------|----------|-------------|
| 多数投票抑制纠正 | "废除多数投票" | 审核团3人评分→加权选优，裁判团3人投票→仍是投票 | **参与者加权收敛投票**，权重=per-tag importance_score（领域专家权重更高） |

## 七、FSM新状态机

```
IDLE → PROFILING → TEAM_FORMING → DISCUSSING → CONVERGING → FORMATTING → COMPLETE
                                    ↑                ↓
                                    └── REBUTTAL ←───┘  (共识<80%→再讨论)
```

| 状态 | 触发条件 | LLM调用 |
|------|---------|---------|
| IDLE | 收到学生输入 | 0 |
| PROFILING | 画像解析 | 1 |
| TEAM_FORMING | Agent自参选+征召 | 0（自评估不调LLM，用importance_score+tag匹配计算） |
| DISCUSSING | 圆桌讨论（最多3轮） | 3~15（按参与Agent数和轮次） |
| CONVERGING | 参与者投票收敛 | 0（纯计算，基于importance_score加权） |
| REBUTTAL | 共识<80%→再讨论1轮 | 2~4 |
| FORMATTING | 格式化+资源生成 | 1~3 |
| COMPLETE | 输出 | 0 |
