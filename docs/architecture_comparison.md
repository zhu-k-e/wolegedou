# 架构重构前后对比文档

> 本文档仅供决策参考，不修改任何正式文件。当前版本 v6.13。

## 一、核心架构流程对比

### 现在（流水线架构）

```
学生提问
  → 学情画像解析(LLM×1)
  → 调度器查表分配Agent(0次LLM)
  → 各Agent独立生成(LLM×2~8，互不可见)
  → 审核团队3人段内评分(LLM×3~9)
  → 跨段一致性审查(LLM×0~2)
  → 最优Agent聚焦输出(LLM×1~3)
  → 裁判团3人裁决(LLM×3~9)
  → 裁判团修改重审循环(LLM×0~6)
  → 格式化 + 资源生成(LLM×1~3)

固定9/19/37次调用 | Agent互不可见 | 外部仲裁
```

### 改后（圆桌协同架构）

```
学生提问
  → 学情画像解析(LLM×1)
  → Agent自主评估置信度+协调器征召(0次LLM)
  → 圆桌讨论：接力式构建答案(LLM×3~15，可见彼此输出)
  → 收敛投票：参与者自投票(0次LLM，纯计算)
  → 分歧→再讨论一轮(可选，LLM×2~4)
  → 格式化 + 资源生成(LLM×1~3)

按需3~20次调用 | Agent可见彼此 | 自收敛
```

## 二、逐维度详细对比

### 2.1 Agent角色与数量

| 维度 | 现在 | 改后 | 变化 |
|------|------|------|------|
| 领域Agent | 10个(不变) | 10个(不变) | — |
| 审核团队 | 3人(Verifier/Skeptic/Evaluator) | **删除** | 领域Agent自己讨论替代 |
| 裁判团 | 3人(事实/逻辑/适用性) | **删除** | 参与讨论的Agent自投票替代 |
| 资源Agent | 1个(不变) | 1个(不变) | — |
| 协调器 | 调度器(查表分配) | 1个协调Agent(征召+管理讨论轮次) | 功能升级 |
| **总数** | **17个角色** | **11个角色** | -6 |

### 2.2 Agent自主性

| 维度 | 现在 | 改后 |
|------|------|------|
| 参选方式 | 被调度器查表指派，无选择权 | 自评估置信度→主动参选，不够则被征召 |
| 交互方式 | 完全独立生成，互不知道对方输出 | 看到初稿后可补充、质疑、修正 |
| 信念更新 | 无（生成完就走） | 有（看到反驳后可修正自己的观点） |
| 决策参与 | 无（审核/裁判是外部人） | 参与（自己投票决定最终答案） |
| 角色切换 | 固定（生成者永远是生成者） | 动态（提初稿者=主导者，补充者=辅助者，质疑者=审查者） |

### 2.3 决策机制

| 维度 | 现在 | 改后 |
|------|------|------|
| "谁最好" | 审核团队3人评分加权选优 | 圆桌讨论中自然涌现（谁的补充被采纳多，谁就是主导者） |
| "够不够好" | 裁判团3人投票裁决 | 参与者自投票收敛（≥80%共识→通过） |
| 分歧处理 | 错误博弈状态机(DEBATING/PROTECTING) | 分歧点→再讨论一轮→再投票 |
| 修改机制 | 裁判团退回Agent修改(最多2次) | 被质疑的Agent在讨论中直接修正 |
| 评分来源 | 审核评分+裁判裁决(外部) | per-tag历史importance_score+本次讨论贡献度(内部) |

### 2.4 FSM状态机

| 现在（10状态） | 改后（8状态） | 变化说明 |
|---------------|-------------|---------|
| IDLE | IDLE | — |
| PROFILING | PROFILING | — |
| DISPATCHING | TEAM_FORMING | 查表→自参选+征召 |
| GENERATING | DISCUSSING | 独立生成→圆桌接力讨论 |
| REVIEWING | **删除** | 外部审核→讨论中同伴质疑替代 |
| FOCUSING | **删除** | 选最优聚焦→讨论收敛后自然形成最终答案 |
| JUDGING | CONVERGING | 外部裁判→参与者自投票 |
| REVISING | REBUTTAL | 退回修改→针对分歧点再讨论 |
| FORMATTING | FORMATTING | — |
| COMPLETE | COMPLETE | — |

### 2.5 LLM调用次数

| 场景 | 现在(固定) | 改后(按需) | 节省 |
|------|----------|----------|------|
| 单领域(概念理解) | 9次 | 3~5次 | 44~56% |
| 跨领域(2段) | 19~25次 | 8~15次 | 37~58% |
| 全链路(4段) | 37~41次 | 15~20次 | 49~59% |
| 简单共识问题(无分歧) | 仍9次 | 3次(提初稿+1轮确认+资源) | 67% |

> 改后调用次数不再固定，取决于：参与Agent数、讨论轮次、分歧程度。简单问题大幅减少，复杂问题仍可控。

### 2.8 四大亮点/创新点

| # | 现在 | 改后 | 评价 |
|---|------|------|------|
| 1 | SOP中间产物机制 | **动态组队机制**(Agent自评估置信度→主动参选) | 从配角→主角，真正体现"协同" |
| 2 | 非多数投票(加权收敛+证据博弈) | **圆桌讨论+加权收敛**(接力式构建+参与者自投票) | 机制更自然，不再是外部仲裁 |
| 3 | 多角色反射(审核+裁判+反向怀疑) | **信念更新与同伴质疑**(Agent可被说服、可修正) | 从"被动被审"→"主动协商" |
| 4 | 贡献记忆(per-tag演化) | 贡献记忆(per-tag演化)(不变) | 仍然核心，但现在是驱动Agent参选权重 |

### 2.10 错误博弈状态机 → 讨论收敛对比

| 现在(错误博弈) | 改后(讨论收敛) | 优势 |
|---------------|--------------|------|
| 2:1→DEBATING(少数举证) | 讨论中有人质疑→被质疑者回应 | 不存在死路径问题(#4) |
| 1:2→PROTECTING(异议保护) | 讨论中少数观点→补充证据自证 | 同一机制覆盖两种情况 |
| 3:0→直接通过 | ≥80%共识→直接通过 | 类似，但阈值可调 |
| 2次修改上限→强制通过 | MAX_DISCUSSION_ROUNDS=3→强制收敛 | 类似，但轮次更灵活 |
| 3名裁判独立审查(互不可见) | 参与者可见彼此(防附和) | 更透明，且可要求"不同意见必须提出" |

### 2.11 全链路降级策略

| 场景 | 现在 | 改后 |
|------|------|------|
| 审核全部失败 | 跳过审核→直接聚焦 | **不再存在**(没有独立审核步骤) |
| 裁判全部失败 | 跳过裁判→直接输出 | **不再存在**(参与者自己投票，不存在"全失败") |
| 无Agent参选 | — | 协调器按标签征召(fallback) |
| 仅1Agent参选(单候选) | 强制补齐次匹配 | 该Agent自审视+不同temperature再生成1份 |
| 讨论不收敛 | — | MAX_DISCUSSION_ROUNDS后强制加权输出 |
| 画像解析失败 | 缓存兜底 | 不变 |

## 七、结论

| 维度 | 现在 | 改后 | 判断 |
|------|------|------|------|
| "多智能体协同"真实性 | ❌流水线 | ✅真协同 | 核心改善 |
| Agent自主性 | ❌无 | ✅有 | 核心改善 |
| 方案书改动量 | — | ~30%重写 | 可接受 |
| 可复用比例 | — | 70-80% | 高 |
| LLM调用成本 | 高(固定) | 低(按需) | 显著改善 |
| 实现复杂度 | 低(流水线) | 中(讨论机制) | 略增，但Agent数减少 |
| 竞赛论证力 | 弱(流水线+外部仲裁) | 强(真协同+自收敛) | 核心改善 |
