2. 学生提问 — 主流程入口

POST /api/ask 核心

学生提交问题，触发 FSM 编排器完整流程：画像 → 调度 → 生成 → 审核 → 聚焦 → 裁判 → 格式化 → 完成。

响应时间：单领域 ~20s · 跨领域 ~27s · 全链路 ~38s。
前端建议：调用后立即拿到 task_id，然后用 WebSocket 订阅 /ws/{task_id} 接收实时状态，不要同步阻塞等待。
请求体 · AskRequest
字段类型必填说明
questionstring是学生当前问题文本
session_idstring是会话 ID，同一会话内多次提问保持一致
historyarray<object>否历史对话（同 session 首次为空），格式 [{role, content}]
请求示例
{
  "question": "什么是 RAG 检索增强生成？",
  "session_id": "sess_abc123",
  "history": []
}
响应体 · AskResponse
字段类型必含说明
task_idstring是本次任务 ID，用于查状态、反馈、答题
session_idstring是会话 ID（回传）
profileobject|null否学情画像 JSON（knowledge_level / background / current_goal 等）
resource_packageobject|null否资源包：{lecture, guide, quiz} 讲义/指南/测试题
judge_verdictobject|null否裁判团裁决：{verdict, opinions, sources}
dispatch_infoobject|null否调度信息：选中了哪些 Agent、各自信度
navigation_roadmapstring|null否学习路径导航文本
clarification_optionsarray<string>|null否澄清选项（问题模糊时返回，让用户选）
errorstring|null否错误信息（非 null 时表示处理失败）
disclaimerstring是AI 内容声明（固定文案）
from_cacheboolean是是否命中离线缓存（true 时响应极快）
响应示例
{
  "task_id": "task_20260719_001",
  "session_id": "sess_abc123",
  "profile": {
    "knowledge_level": "intermediate",
    "background": "cs_student",
    "current_goal": "learn_basics"
  },
  "resource_package": {
    "lecture": "RAG 是 Retrieval-Augmented Generation...",
    "guide": "步骤 1：准备文档...",
    "quiz": [{"question": "...", "options": [], "answer": "B"}]
  },
  "judge_verdict": {
    "verdict": "pass",
    "opinions": [],
    "sources": []
  },
  "dispatch_info": {
    "selected_agents": ["agent_004"],
    "primary_domain": "RAG"
  },
  "navigation_roadmap": "建议学习路径：1. 理解检索原理...",
  "clarification_options": null,
  "error": null,
  "disclaimer": "⚠️ 以上内容由 AI 生成，仅供参考...",
  "from_cache": false
}

3. 查询任务状态

GET /api/status/{task_id} 轮询备用

查询任务当前 FSM 状态。WebSocket 不可用时可用轮询。

注意：服务重启后内存状态会丢失，返回 UNKNOWN。优先用 WebSocket。
路径参数
参数类型必填说明
task_idstring是任务 ID（从 /api/ask 响应获取）
响应体 · StatusResponse
字段类型说明
task_idstring任务 ID
statestringFSM 状态名，见枚举表
dataobject|null附加数据（如 revision、session_id）
响应示例
{
  "task_id": "task_20260719_001",
  "state": "GENERATING",
  "data": { "revision": 0, "session_id": "sess_abc123" }
}

4. 学生反馈

POST /api/feedback 核心

学生对本次回答的反馈，后端据此更新 Agent 贡献记忆并可能触发延伸路径。

请求体 · FeedbackRequest
字段类型必填说明
task_idstring是任务 ID
session_idstring是会话 ID
agent_idstring是被反馈的 Agent ID（从 dispatch_info 获取）
function_tagstring是功能标签（从 dispatch_info 获取）
feedback_typestring是反馈类型，见枚举
commentstring|null否文字反馈
feedback_type 枚举
helpful not_helpful content_error difficulty_mismatch
请求示例
{
  "task_id": "task_20260719_001",
  "session_id": "sess_abc123",
  "agent_id": "agent_004",
  "function_tag": "RAG",
  "feedback_type": "helpful",
  "comment": "讲得很清楚"
}
响应体 · FeedbackResponse
字段类型说明
successboolean是否成功
messagestring结果描述
extension_triggeredstring|null触发的延伸路径：recheck / redimension / null
反馈联动：
  • helpful → Agent accuracy +0.02
  • not_helpful → Agent accuracy -0.02
  • content_error → 触发 RECHECK（重新核查）
  • difficulty_mismatch → 触发 REDIMENSION（重新定维，不影响 Agent 评分）

5. 答题验证

POST /api/quiz_submit 核心

学生做完资源包里的测试题后提交，后端计算正确率并触发延伸路径。

请求体 · QuizSubmitRequest
字段类型必填说明
task_idstring是任务 ID
session_idstring是会话 ID
answersarray<object>是答题结果
answers 元素结构
字段类型说明
questionstring题目文本
user_answerstring学生答案
is_correctboolean是否正确（前端判分后传）
请求示例
{
  "task_id": "task_20260719_001",
  "session_id": "sess_abc123",
  "answers": [
    { "question": "RAG 的全称是？", "user_answer": "Retrieval-Augmented Generation", "is_correct": true },
    { "question": "向量检索用什么相似度？", "user_answer": "欧氏距离", "is_correct": false }
  ]
}
响应体 · QuizSubmitResponse
字段类型说明
task_idstring任务 ID
accuracyfloat正确率（0.0 ~ 1.0）
actionstring延伸动作：redimension / advance / recheck
new_resourcesobject|null降维/进阶时生成的新资源包
followup_questionsarray<string>|null后续推荐问题
正确率联动（方案书 6.1.3）：
  • < 60% → REDIMENSION（深度降维）
  • 60% ~ 85% → REDIMENSION（轻度降维）
  • ≥ 85% → ADVANCE（进阶挑战）

6. 知识库接口（调试用）

这 4 个接口主要给知识库团队和运维用，前端一般不需要对接。如果前端要做"知识库管理面板"可以对接。

GET /api/kb/health 调试

知识库健康检查：返回当前后端模式（numpy/chromadb/stub）、chunk 总数、依赖状态。

响应示例
{
  "mode": "numpy",
  "total_chunks": 34154,
  "embedding_model": "bge-m3",
  "healthy": true
}
POST /api/kb/import 调试

导入文档目录（递归导入 .md / .txt / .pdf）。

请求体
{
  "path": "data/raw_docs",
  "agent_ids": ["agent_004"]  // 可选，不传自动匹配
}
响应
{
  "success": true,
  "imported_count": 128,
  "total_chunks": 34282,
  "message": "导入完成"
}
POST /api/kb/import-file 调试

导入单个文件。

请求体
{
  "path": "data/raw_docs/rag_tutorial.md",
  "agent_ids": null
}
GET /api/kb/search 调试

检索测试（不经过 LLM，直接看知识库返回什么）。

Query 参数
参数类型必填默认说明

top_kint否3返回条数（1~20）

7. WebSocket — FSM 实时状态推送

WS /ws/{task_id} 核心

前端连接后，编排器每次 FSM 状态变更都会推送消息。用于实时展示"当前 FSM 状态：XXX"。

连接 URL
ws://localhost:8000/ws/task_20260719_001
前端连接示例（JS）
const taskId = "task_20260719_001";
const ws = new WebSocket(`ws://localhost:8000/ws/${taskId}`);

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  console.log("收到状态:", msg.state);
  // 更新 UI 显示当前 FSM 状态
};

ws.onclose = () => console.log("WebSocket 断开");
推送消息格式
{
  "type": "fsm_state",
  "task_id": "task_20260719_001",
  "state": "GENERATING",
  "data": {
    "profile": { /* 学情画像，PROFILING 阶段才有 */ }
  }
}
消息字段说明：
  • type：消息类型，目前只有 "fsm_state"，后续可能扩展
  • state：FSM 状态名，见下方枚举表
  • data：附加数据，不同状态携带不同内容（如 PROFILING 携带 profile）
断线重连：WebSocket 不可用时降级到 GET /api/status/{task_id} 轮询（建议 1s 一次）。

9. 前端调用流程（推荐）

典型一次提问的完整调用链： 
// 1. 学生提问
POST /api/ask  { question, session_id, history }
  → 立即返回 { task_id, ... }

// 2. 用 task_id 订阅 WebSocket 接收实时状态
new WebSocket(`ws://localhost:8000/ws/${taskId}`)
  → 持续收到 { type: "fsm_state", state: "PROFILING" → "GENERATING" → ... → "COMPLETE" }

// 3. （可选）轮询备用
GET /api/status/{task_id}  // WebSocket 断线时用

// 4. 学生做资源包里的测试题后提交
POST /api/quiz_submit  { task_id, session_id, answers }
  → 返回 { accuracy, action: "redimension" | "advance" }

// 5. 学生对回答反馈
POST /api/feedback  { task_id, session_id, agent_id, function_tag, feedback_type }
  → 返回 { success, extension_triggered }
前端注意事项：
  1. /api/ask 响应时间较长（20~38s），前端必须有 loading 动画 + WebSocket 实时状态展示
  2. session_id 前端自己生成（UUID 即可），同一会话内保持不变
  3. history 前端维护，每次提问带上前几轮对话（建议最近 5 轮）
  4. 响应里 clarification_options 非 null 时，问题模糊，前端弹出让用户选
  5. 响应里 error 非 null 时，展示错误信息 + 重试按钮
  6. disclaimer 字段必须展示在 AI 回答下方（合规要求）
  7. from_cache 为 true 时响应极快，可标注"缓存命中"
