### 🔴-3 延伸路径缺少实现指导——FSM伪代码和状态图缺失

**位置**：6.1.3节延伸路径 vs 6.1.2节编排器伪代码

**矛盾内容**：
- 6.1.3详细描述了延伸路径（QUIZ_EVAL→REDIMENSION/ADVANCE/RECHECK→HEURISTIC_FOLLOWUP）
- 但6.1.2的编排器伪代码只覆盖主FSM（IDLE→...→COMPLETE），**完全没有延伸路径的伪代码**

**严重性**：延伸路径是v6.15新增的核心设计（对齐赛题"动态迭代闭环"和"启发式追问导学"），但实现层面完全悬空。评委问"延伸路径怎么在编排器中实现"，方案书没有答案。

**修复建议**：在6.1.2伪代码中补充延伸路径的异步触发机制（如：COMPLETE后进入事件等待状态，监听学生反馈/答题提交事件），或在6.1.1 FSM状态定义中补入延伸路径状态。

### 🔴-4 候选辩论证据→裁判团重审机制不明确

**位置**：4.4.2节分歧解决状态机

**矛盾内容**：
- 候选Agent辩论的设计：落选候选质疑→获胜候选辩护→两方证据合并提交给裁判团
- 状态机描述：证据充分→[REVISING]，证据不足→[PASSED]
- **但关键问题**：裁判团已经做了独立审查并形成2:1分歧，辩论证据提交后，裁判团如何"消费"这些新证据？
  - 是3名裁判全部重新审查？（状态机说"修改后3名裁判全部重新审查"，但这是针对REVISING状态的Agent修改后的重审，不是针对辩论证据的重审）
  - 还是仅少数方/多数方查看辩论证据后调整判断？（没有说明）
  - 辩论证据是否改变裁判团的判断流程？如果改变，是否需要新一轮独立审查？如果不改变，辩论的意义是什么？

**严重性**：候选辩论是Debate论文核心落地+创新点1的关键机制，但"辩论证据如何影响裁判团决策"的逻辑链断裂。评委追问这个机制时会发现说不清楚。

**修复建议**：明确辩论证据的消费路径——建议方案：辩论证据与少数方举证合并，作为REVISING状态的输入（如果证据揭示真实问题→退回Agent修改；如果证据不充分→维持原判PASSED）。需要在4.4.2状态机中补充"辩论证据→裁判团判定证据是否充分→REVISING或PASSED"的明确路径。

### 🔴-5 跨段一致性审查处理方式矛盾

**位置**：6.1.2节编排器伪代码 vs 4.3.3节冲突修改规则

**矛盾内容**：
- 4.3.3明确说：发现冲突后"指定相关Agent修改"（小改不需再过裁判团，大改需要）
- 但6.1.2伪代码在REVIEWING阶段写道：
  ```python
  if consistency_issues:
      state = "GENERATING"  # 指定Agent修改后重跑
  ```
  `state = "GENERATING"` 会重跑整个GENERATING阶段（重新生成所有候选），而不是"指定某个Agent修改"
- 这与4.3.3的"只改冲突的一句或几句话"设计矛盾

**严重性**：伪代码实现与设计描述不一致。如果按伪代码实现，跨段冲突会触发全量重生成（浪费调用+时间）；如果按4.3.3实现，伪代码是错的。

**修复建议**：修改伪代码，跨段一致性审查发现冲突时，不回到GENERATING，而是在FOCUSING阶段由指定Agent做小修改。或者增加一个MINOR_REVISING状态专门处理小修改。

## 🟡 显著问题（10个）

### 🟡-1 LLM JSON合格率~95%缺乏依据

**位置**：3.5.2节

**问题**：声称"首次输出符合Schema 70-80%"、"后处理修复 +15%"、"重试+5%"、"最终合格率~95%"。这些数字没有实验依据。实际LLM JSON输出合格率取决于Schema复杂度和模型能力——FocusedOutput有6个必填字段+嵌套对象+数组约束，GPT-4o首次合格率可能低于70%。

**影响**：如果实际合格率远低于95%，大量退回重试会显著增加响应时间和成本。评委可能质疑数据来源。

**建议**：改为保守估计"预期合格率≥85%"，并补充"上线后实测校准"的说明。

### 🟡-2 self_confidence 间接影响评分与"不计入评分"矛盾

**位置**：3.4.4节

**问题**：
- 规则声明"self_confidence不计入审核团队评分"
- 但双低触发RAG（两个候选self_confidence<0.5）→重新生成→审核团队评分新输出
- self_confidence通过触发RAG间接影响了审核团队评分的对象（从原始输出变为RAG增强后的输出）
- 这不是"不计入评分"——它改变了评分的输入

**影响**：逻辑不自洽，评委可能追问"self_confidence到底算不算影响评分"。

**建议**：修改描述为"self_confidence不直接计入评分公式，但通过RAG触发机制间接影响评分输入"。或补充说明：RAG增强后的输出是新的一次完整流程，审核团队评分的是新输出而非旧输出。

### 🟡-8 Agent池=同一LLM+不同Prompt的概念表述风险

**位置**：3.1-3.2节

**问题**：
- 10+1个"Agent"本质上是同一个LLM（DeepSeek-V3）的不同System Prompt实例
- 方案书用"Agent池"、"候选Agent"、"Agent_1到Agent_10"的表述，暗示这些是具有不同能力的独立实体
- 实际上它们只是Prompt模板的切换——Agent_3在RAG上"擅长"不是因为Agent_3有独特的知识，而是因为它的Prompt强调了RAG
- 这在多智能体领域是标准做法（MetaGPT也是如此），但表述可能误导评委以为这些是真正的差异化模型

**影响**：评委如果追问"10个Agent是10个不同模型吗"，会发现实际是同一模型。不过这不算造假——MetaGPT也用同模型不同角色。关键是表述要准确。

**建议**：在3.1节补充说明："每个领域Agent是同一LLM的不同Prompt角色实例，差异来自System Prompt而非模型本身。这是多智能体协作的标准范式（MetaGPT论文亦采用此方式）。Agent池的价值在于Prompt专业化+动态遴选，而非模型差异化。"

## 🟢 轻微问题（4个）

### 🟢-1 成本估算$0.01/call可能偏低

**位置**：8.5.2节

DeepSeek-V3实际定价为输入$0.27/M tokens、输出$1.10/M tokens。一个典型的候选输出（含FocusedOutput JSON）可能消耗500-1500 output tokens，实际成本可能在$0.002-$0.005/call，比$0.01低或相近——但聚焦输出和裁判审查的输出更长，可能超过$0.01。建议标注"为估算方便取均值$0.01，实际随输出长度浮动"。

---

### 🟢-2 双低RAG阈值0.5可能过于严格

**位置**：3.4.4节

"两个候选self_confidence都<0.5才触发RAG"——如果一个0.49一个0.85，不触发；但0.49已经很低了。建议考虑"任一候选<0.4 + 另一候选<0.6"的宽松组合触发，或维持现有设计但在8.3.1示例中说明为何阈值选择0.5。

---

### 🟢-3 知识库跨语言检索质量验证方法不具体

**位置**：7.2.3节 + 6.4节

声称使用bge-m3跨语言检索，但验证方法只说"从知识库中随机抽取100个核心知识点"，没有专门测试中文问题→英文文档的检索准确率。建议在7.2.3补充跨语言检索专项测试（如50道中文问题→验证英文文档召回率）。

### 🟢-4 离线评估队列"每周10道标准测试题"来源未说明

**位置**：5.5.2节

淘汰后的Agent进入离线评估，"每周用10道标准测试题评估"——但标准测试题从哪里来？是人工编写还是从知识库自动生成？建议补充来源说明。

## 与赛题对齐审核的区别

| 维度 | 赛题对齐审核 | 可行性检查 |

| 检查对象 | 赛题要求是否被方案书覆盖 | 方案书自身逻辑是否自洽、能否落地 |

| 修复方向 | 补内容 | 修逻辑/补机制/统一表述 |
