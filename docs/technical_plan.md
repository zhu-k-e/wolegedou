> 目的：为团队15天内判断"这个题能不能做"提供具体技术思路，不是开发计划。

## 难点一：多Agent协同架构（如何不沦为简单串联）

### 问题

评审明确扣分："退化为单模型直接生成、无协同机制"。你把诊断→生成→审核串起来不算创新，评审一眼看出是调了三次API。

### 技术方案：星型辩论拓扑

```
                    ┌──────────────┐
                    │   学习画像库   │
                    └──────┬───────┘
                           │
    ┌──────────────────────┼──────────────────────┐
    │                      │                      │
    ▼                      ▼                      ▼
┌────────┐  质疑   ┌──────────┐  审核   ┌──────────┐
│ 生成   │◄──────►│ 辩论协调   │◄──────►│ 审核裁判  │
│ Agent  │  反驳   │  Center   │  裁决   │  Agent   │
└───┬────┘        └─────┬────┘        └────┬─────┘
    │                   │                   │
    │          ┌────────┴────────┐          │
    │          │   知识库检索     │          │
    │          └────────┬────────┘          │
    │                   │                   │
    └───────────────────┼───────────────────┘
                        ▼
                 ┌──────────────┐
                 │   共享上下文   │
                 │  (辩论日志)   │
                 └──────────────┘
```

### 关键创新点（和简单串联的区别）

| 简单串联 | 我们的方案 |
|---------|-----------|
| Agent A输出 → Agent B输入，单向 | 生成Agent和审核Agent**互相质疑反驳**，双向博弈 |
| 审核不过就重试，最多3次 | 辩论有**裁决机制**——分歧无法解决时，调用知识库原文做最终判断 |
| 看不到中间过程 | **辩论日志全程保留**，评委能看见谁质疑了什么、怎么解决的 |
| 所有学习者走同一流程 | 根据学情**动态路由**——初学者走简化路径，进阶者添加"挑战生成"分支 |

### 具体实现方式

```
流程：
1. 学情诊断Agent输出画像 → 存入共享上下文
2. 生成Agent出第一版内容 → 附带"知识溯源"（每一段标注知识库来源）
3. 审核Agent对照知识库逐条核查 → 标注质疑点
4. 如果审核通过 → 直接输出
5. 如果审核不通过 → 辩论协调Center启动：
   a. 把审核意见发给生成Agent，要求回应
   b. 生成Agent可以：接受修改 / 引用知识库反驳
   c. 协调Center根据知识库原文裁决
   d. 裁决结果写入辩论日志
6. 最终输出：内容 + 辩论日志 + 溯源标注
```

### 15天验证标准

- [ ] 单条链路跑通：学情输入 → 生成 → 审核 → 输出
- [ ] 辩论链路跑通：审核不通过时，生成Agent能回应质疑
- [ ] 辩论日志可查看

**不需要在15天内做到完美，只需要证明"这个机制能跑"。**

## 难点二：防幻觉机制（辩论/交叉验证）

### 问题

大模型天生会胡说。比赛要求"专业知识谬误率<5%"，但你不约束它，幻觉率可能30%+。

### 技术方案：双层验证 + 辩论协议

#### 第一层：事实核查（自动的）

```
审核Agent工作流程：
对于生成内容中的每一段：
  1. 提取"声称的事实" → 比如 "Pandas的groupby默认不包含NaN分组"
  2. 用RAG检索知识库：这个说法有没有来源支持？
  3. 如果检索到匹配 → 标注"已溯源，来源：[文档名/段落号]"
  4. 如果检索不到 → 标注"疑似幻觉，事实存疑"
  5. 如果检索到矛盾信息 → 标注"与知识库冲突，建议修正为：[原文]"
```

#### 第二层：逻辑一致性检查

```
审核Agent额外检查：
- 前文说"用fillna(0)填充"，后文说"缺失值用均值填充" → 自相矛盾
- 声称"适合初学者"但内容里出现了lambda和apply → 难度不匹配
- 代码示例的输入输出对不上 → 逻辑断裂
```

#### 辩论协议（核心）

双方用结构化JSON通信，不是自由文本：

```json
// 审核Agent发起质疑
{
  "type": "challenge",
  "target": "段落3-第2句",
  "claim": "Pandas的groupby默认排除NaN",
  "evidence": "Pandas官方文档v2.1.0第5.3节：groupby默认保留NaN分组",
  "suggested_fix": "修正为：groupby默认保留下NaN，如需排除使用dropna=True"
}
```

```json
// 生成Agent回应
{
  "type": "response",
  "verdict": "accept",  // 或 "rebut"
  "reason": "核查知识库，官方文档确实写的是保留",
  "revision": "修正后的内容..."
}
```

### 为什么这个方案可行

| 顾虑 | 解答 |
|------|------|
| "辩论会不会无限循环" | 最多两轮辩论，无法解决就降到知识库原文裁决 |
| "审核Agent自己也会幻觉" | 审核Agent不生成内容，只做"与知识库比对"——这是检索任务，不是生成任务 |
| "知识库不全怎么办" | 审核不匹配时不直接否定，而是标注"知识库未覆盖，置信度低" |

### 15天验证标准

- [ ] 构造5个"故意写错"的生成内容，审核Agent能否全部揪出
- [ ] 构造1个辩论场景，看辩论日志是否完整记录了质疑→回应→裁决

## 难点三：个性化量化评估

### 问题

比赛要求"适配准确率≥85%"。怎么量化？总不能用嘴说"我们觉得适配了"。

### 技术方案：向量相似度匹配

#### 学习者画像 → 量化向量

```
输入数据                 →  画像维度
─────────────────────────────────────────
学历(专科/本科/硕士)       →  theoretical_base: [0-1]
自评技能水平               →  practical_level: [0-1]
前置知识测试得分(10题)     →  test_score: [0-1]
学习目标(入门/进阶/专项)    →  goal_difficulty: [0-1]
─────────────────────────────────────────
学习者向量 = [0.6, 0.3, 0.5, 0.2]
```

#### 学习资源 → 难度向量

```
资源属性                 →  难度维度
─────────────────────────────────────────
内容复杂度(概念/实操/混合)  →  complexity: [0-1]
前置知识要求               →  prerequisites: [0-1]
实操占比                  →  practical_ratio: [0-1]
目标匹配度                →  goal_match: [0-1]
─────────────────────────────────────────
资源向量 = [0.5, 0.4, 0.6, 0.3]
```

#### 计算适配度

```
适配分数 = cosine_similarity(学习者向量, 资源向量)

分数 > 0.85  → 高适配
分数 0.7-0.85 → 中适配
分数 < 0.7  → 低适配（不满足比赛指标）
```

#### 验证方法

不依赖真实学生，用GPT自评测：

```
1. 生成10个差异化学员画像（用GPT伪造）
   例：学员A是计算机本科，会写代码但不会数据分析
   例：学员B是文科背景，零基础，目标是入门

2. 系统为每个学员生成一套学习资源

3. 用另一个GPT实例（盲评）打分：
   "这个学员的背景是XXX，生成的资源难度是否合适？1-5分"
   
4. 计算：评分≥4的比例 → 就是你的"适配准确率"
```

### 为什么这个方案可行

| 顾虑 | 解答 |
|------|------|
| "向量维度怎么定" | 先用4个基础维度，后续可加，不影响框架 |
| "GPT盲评靠谱吗" | 比赛评委也是人打分，你用GPT模拟评审是合理的验证手段 |
| "85%好达到吗" | 只要你画像维度合理，算法适配本身不难达到——难的是知识内容质量 |

### 15天验证标准

- [ ] 定义好学情画像的输入字段（至少4个维度）
- [ ] 用GPT生成3组差异化测试数据
- [ ] 跑通画像→资源生成→盲评的全流程
- [ ] 算出一个适配准确率数字（哪怕是手工算的）

## 难点四：知识库建设

### 问题

知识库是RAG的基础，没有它审核Agent无法校验。但你们说"不会建"。

### 技术方案：结构化搬砖

#### 不用创造内容，只需要搬运

```
知识库素材来源（全部公开免费）：

Pandas官方文档     →  https://pandas.pydata.org/docs/
NumPy用户指南      →  https://numpy.org/doc/stable/user/
Matplotlib教程     →  https://matplotlib.org/stable/tutorials/
Seaborn教程        →  https://seaborn.pydata.org/tutorial.html
Python官方教程     →  https://docs.python.org/zh-cn/3/tutorial/
Kaggle入门案例     →  搜索"data analysis notebook" 找10篇
```

#### 一键建库流程

```
步骤1：下载文档
  - 用Python写个脚本，批量下载上述网站的HTML/PDF
  - 或者直接用浏览器"另存为"保存网页

步骤2：清洗
  - 提取纯文本，去掉导航栏、广告、代码高亮标记
  - 保留代码块（带语言标记）

步骤3：切片
  - 每个切片500-1000字符，相邻切片重叠200字符
  - 保留来源URL和段落编号

步骤4：向量化
  - 用 sentence-transformers（免费本地模型，不调API）
  - 生成768维向量

步骤5：入库
  - 存入 ChromaDB（pip install chromadb，一行代码的事）
  - 自然语言查询 → 返回最相关文档片段

总代码量：约150行Python
单人耗时：2-3天（主要是下载和清洗）
```

#### 已有项目骨架中的对应代码

```python
# knowledge_base/build_kb.py 已经搭好了框架
# knowledge_base/document_loader.py 负责读文档
# knowledge_base/vector_store.py 封装ChromaDB
# knowledge_base/retriever.py 提供检索接口

# 你只需要往 knowledge_base/raw_docs/ 里丢文档
# 然后运行：python -m knowledge_base.build_kb
```

### 15天验证标准

- [ ] `raw_docs/` 里有至少10篇文档
- [ ] `build_kb.py` 能跑通
- [ ] `retriever.search("Pandas groupby用法")` 能返回相关文档片段

**重要：15天不需要建完，10篇文档就够验证检索链路。**
