## 三、主要缺口清单（按优先级）

### P0 致命 / 阻断级
1. **确认报名状态**（报名 6/30 已截止）—— 若未报名，立即联系发榜单位/学校补救。
2. **前端可视化 UI 缺失** —— 无前端工程。后端已具备：`/api/report` 三组件、`/api/status`、`WS /ws/{task_id}`（含各阶段状态/裁判结论）。需前端团队把"多 Agent 调度过程 + 裁判辩论 + 决策链路"做成可视化界面。
3. **量化指标不达标** —— 接 100 条真值 `reference_answer_points`，修正指标定义（幻觉率用事实核查、适配率用 overall_match_rate、覆盖率用知识点清单），跑到幻觉 <5% / 适配 ≥85% / 覆盖 ≥90%。
4. **源码仓库开放评审权限** —— 竞赛要求源码可评审。当前决定"不 commit/push"，与提交形式冲突。提交前必须开放（哪怕新建私有库给评审账号）。

### P1 重要级
5. **降维资源回传 bug** —— `orchestrator._do_redimension` 末行误调 `_do_heuristic_followup` 丢弃 `reduced_resource_package`；`QuizSubmitResponse.new_resources` 始终未赋值。前端拿不到新资源。
6. **clarification 静态不驱动迭代** —— `matcher._generate_clarification_options` 返回 6 个固定值，忽略 profile，且无接口回收选择。建议改为基于 profile 动态生成，或至少明确其为"建议"并在文档说明。
7. **演示视频** —— 录 10 分钟：差异化学情输入 → 多 Agent 调度可视化 → 资源生成完整闭环。
8. **交付文档** —— 设计实现方案、PPT、部署说明、数据合规与脱敏说明。
9. **测试数据套装** —— 整理"输入画像 + 中间协同数据 + 最终资源"成套示例（≥3 组差异化），切出知识库交付子集。

### P2 加分 / 隐患
10. **场景泛化说明** —— 目前仅 AI 领域，文档需论证向智能制造等泛化能力（架构可迁移）。
11. **DB 路径分裂** —— `config.db_path` 相对路径致 `data/` 与 `backend/data/` 两套库，统一避免演示数据错乱。
12. **KB 噪声** —— 阿拉伯语 `_ar-pages_` 切片是检索噪声，需过滤（demo 已暴露）。
