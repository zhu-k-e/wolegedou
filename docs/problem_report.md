## 🔴 高严重度问题（必须修复）

### 问题1：响应时间估算严重乐观

**位置**：第353-376行（2.3.3节表格）

**问题描述**：
方案书声称"~20s"完成9-10次LLM调用，但实际上：
- 每次LLM API调用通常需要2-5秒（取决于模型、网络、输出长度）
- 9-10次调用即使并行也需要27-50秒
- 还未计入审核团队（3人）+ 裁判团（3人）的额外调用

**实际情况估算**：
| 领域数 | 方案书声称 | 实际情况（并行优化后） |
|--------|------------|-------------------|
| 1 | ~20s | ~12-15秒 |
| 3 | ~20s | ~30-40秒 |
| 5 | ~25s | ~40-50秒 |
| 8-10 | ~30s | 超过60秒 |

**影响**：
- 用户体验极差（超过3秒响应时间用户就会不耐烦）
- 挑战杯演示可能失败（评委不会等1分钟）

**解决方案**：
1. 区分"快速模式"和"高质量模式"
2. 快速模式：减少候选数、简化审核（~12秒）
3. 高质量模式：保留完整流程（~30秒），UI明确提示
4. 超过5领域：触发"分阶段回答"

**修改位置**：第353-376行

### 问题2：LLM调用次数过多，成本不可持续

**位置**：第353-376行（同一表格）

**问题描述**：
8-10个领域需要73-91次LLM调用，成本过高：
- 按GPT-4o定价：$0.005-0.01/次调用
- 8领域问题：$0.365-0.73/次问答
- 每天100次问答：$36.5-73/天 = $1095-2190/月

**对比**：
- 商业AI培训产品（如Coursera）：单次问答成本<$0.01
- 本方案：单次问答成本$0.37-0.73（37-73倍）

**影响**：
- 系统无法商业化
- 挑战杯演示成本高（如果需要现场演示）

**解决方案**：
1. 引入"早停机制"（节省20-30%调用）
2. 引入"语义缓存机制"（节省10-15%调用）
3. 采用"分层调用策略"（低成本模型用于候选输出，高质量模型用于聚焦输出）
4. 成本估算修正：单次问答成本降至$0.03-0.15

**修改位置**：在第489行之后新增"成本控制机制"一节

**影响**：
- 如果实现为"同一会话中继续"，增加系统复杂度
- 如果实现为"新开API调用"，则浪费已生成的输出

**解决方案**：
1. 明确默认采用"方案1：新开API调用"（实现简单）
2. 说明"方案2"是可选优化（未来版本）

### 问题8：增量更新机制可能导致学情画像不准确

**位置**：第168-185行（2.2.4节）

**问题描述**：
"学情只升不降"可能不合理：
- 场景：学生先问高级问题（知识级被评为"进阶"），然后问基础问题
- 按方案书逻辑，知识级不会降级，永远是"进阶"
- 但实际上学生可能是在复习基础

**影响**：
- 学情画像可能失真
- 影响后续Agent选择和资源生成

**解决方案**：
1. 改为"滑动窗口评估"（根据最近3次问题动态评估）
2. 允许升降级（更灵活）
3. 或者，保留"只升不降"但添加"手动重置"功能

**修改位置**：第168-185行

方案书声称"在原有Prompt末尾添加审查任务"不增加调用，但实际：

- 成本控制失效

**解决方案**：
1. 明确"可能增加少量调用"（诚实）
2. 提供优化方案（将跨段一致性审查合并到"裁判团"阶段）
3. 修正响应时间估算（增加~3秒）

### 问题10：LLM输出严格JSON Schema的成功率可能很低

**位置**：第647-750行（3.5节聚焦输出Schema）

**问题描述**：
要求LLM输出严格JSON，且包含10+字段：
- LLM经常输出格式错误的JSON（缺字段、类型错误、Hallucination）
- 严格JSON Schema的成功率可能只有60-70%

**影响**：
- 系统稳定性差
- 需要大量异常处理

**解决方案**：
1. 添加"JSON后处理机制"（解析、修复、重试）
2. 估算成功率：后处理后90-95%
3. 说明重试策略（最多重试2次）

**修改位置**：第647-680行
